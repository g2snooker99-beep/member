# เริ่มระบบระหว่างเดือนและเชื่อมสต๊อก

- เลือกเวลาเริ่มจริงในวันนี้ (Asia/Bangkok, ISO 8601 ระบุ +07:00) ใช้ค่าเดียวกันใน `MEMBER_REWARDS_V2_START_AT` และ `G2_REWARDS_V2_START_AT` ห้ามย้อนหลังเวลาเพื่อไม่ให้บิลเดิมเปลี่ยนกติกา
- การเริ่มกลางเดือนจะเก็บสิทธิ์รอบเดิมสำหรับเดือนนั้น ใช้กติกาเดิมสำหรับบิลก่อนจุดเริ่ม และไม่โอนหรือรีเซ็ตแต้มเดิมโดยอัตโนมัติ
- ตรวจสอบ PostgreSQL เป้าหมายและ deploy migration `006_reward_stock.sql` ก่อนเปิดสวิตช์ `G2_REWARD_STOCK_ENABLED`; ตั้ง `G2_REWARD_STOCK_SECRET` (สุ่ม 32 bytes รูป hex) ให้ตรงกันที่ Render และ Firebase Secret Manager โดยไม่ใส่ค่าใน Git
- แอดมินเลือกสินค้า POS และจำนวนต่อสิทธิ์สำหรับรางวัลที่จ่ายออกจากสต๊อก ส่วนลดหรือเวลาฟรีเลือกไม่ตัดสต๊อก
- ยืนยัน QR จะจองของจากสต๊อกจริงก่อนหักแต้ม หากสต๊อกหมดจะไม่หักแต้ม หากแต้ม/โควตาใช้ไม่ได้ ระบบคืนของเมื่อ Firestore ยืนยันว่ารายการถูกยกเลิก กรณีเครือข่ายหลุดรายการที่ยังไม่ทราบผลจะไม่คืนสต๊อกจนกว่าจะตรวจสถานะได้
- ก่อนเปิดลูกค้า ทดสอบในระบบแยก: ของเหลือ 1 ชิ้นแลกแข่งกับการขาย, QR เดิมซ้ำ, Firestore ยืนยันแต่ตอบกลับขาดหาย, คืนของเมื่อ QR หมดอายุ, ข้ามเดือน และเทียบรายงานนับสต๊อกจริง
